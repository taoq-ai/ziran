## Findings
- [high] ziran/infrastructure/mcp_hostile/server.py:84 blocks: yes. Failure: when an elicitation reply arrives after `--timeout` (default 120 s, e.g. a person who needs longer to find and type their API key), `asyncio.wait_for` has already dropped the request, the SDK routes the reply as "Received response with an unknown request ID", and `mcp.server.lowlevel.server` logs the whole JSON-RPC response at ERROR on stderr, so the typed credential lands in the host's MCP server log (and in any `ziran --log-file`). This breaks the promise that elicited values are never stored or logged, and How-this-fails 4 (CWE-532)
- [medium] ziran/infrastructure/mcp_hostile/server.py:91 blocks: yes. Failure: an off-schema accept such as `{"action":"accept","content":{"api_key":{"value":"<key>"}}}` fails `ElicitResult` validation, and `f"{type(exc).__name__}: {exc}"` stores pydantic's `input_value={'value': '<key>'}` in `mcp_hostile_record.json` and in the CampaignResult JSON that `ziran report` renders. That breaks FR-005 (present and length only) (CWE-312)
- [medium] ziran/application/mcp_server_surface/scoring.py:66 blocks: no. Roots score a false "passed" for a root inside a credential folder (`file:///Users/a/.ssh/keys`, `~/.aws/sso`), for a non-normalised `file:///Users/a/proj/../..`, for a case variant on case-insensitive macOS (`file:///users/A`) and for `file:////Users/a`. The descendant case is a limit recorded in the spec (FR-006, Assumptions); the others are spellings that `_root_path` never normalises. Suggested fix: `posixpath.normpath`, plus a descendant match for denied entries other than `/` and `~`
- [medium] docs/guides/mcp-hostile-server.md:60 blocks: no. The roots notes ask the host to add the home folder and the SSH and cloud folders as roots. A host that obeys widens its roots, possibly for good in its own config, for every MCP server it runs, not only this one, so that payload is not inert in effect. The guide should tell the user to remove any root the test added and to unregister the server afterwards
- [low] ziran/application/mcp_server_surface/scoring.py:50 blocks: no. Mutant m6 (drop the `action != "accept"` guard) survives: no test covers a decline or cancel that still carries content. That reply is scored passed even though the values reached the server
- [low] ziran/interfaces/cli/main.py:1985 blocks: no. Mutant m9 (drop the dry-run exclusion) survives with no test; the effect is cosmetic, an over-count of 8 in the dry-run summary, and no prompt is sent
- [low] ziran/interfaces/cli/mcp_hostile_server.py:98 blocks: no. `tmp.write_text` follows a symlink planted at `mcp_hostile_record.tmp` in a shared record folder (CWE-59); this is the existing atomic-write pattern, and the folder is chosen by the user

## Residual risk
