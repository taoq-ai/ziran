## Summary
The acceptance criterion (each of `AML.TA0000` and `AML.TA0001` has at least one covered
technique) is already met on develop: 3/4 and 7/7. This feature closes #264 by (1) rewriting the
"Coverage scope (honest)" section of `docs/reference/benchmarks/atlas-mapping.md` with the real
per-technique counts and the reasoning behind them, (2) ticking the roadmap line, and (3) adding
one assertion to the ATLAS coverage integration test so a regression to zero fails CI. No vectors,
no source, no script change.

## Design decision: document, do not add staging vectors
The issue's option 2 (dedicated recon/staging vectors) is rejected per the release brief:
staging techniques (T0005 Create Proxy AI Model, T0042 Verify Attack, T0043 Craft Adversarial
Data) describe adversary-side preparation with no observable outcome against the target, so a
vector cannot pass or fail on them; new vectors tagged with them would only pad counts. Option 1
(tag every vector with T0040/T0047) is also not applied. The existing tags already give both
tactics coverage; the docs explain what that coverage means.

## Design decision: `coverage-comparison.md` is left alone
It is generated by `benchmarks/generate_all.py` (snapshot 2026-04-22, 639 vectors). Its
technique fractions for these tactics (3/4, 7/7) agree with the current run; its per-tactic
vector roll-ups (TA0000 915, TA0001 626) are stale like every other number on that page.
Hand-editing would be overwritten on regeneration; regenerating rewrites the whole page (out of
scope). The rewritten atlas-mapping section quotes only per-technique counts and tactic
fractions, never the roll-up, so the pages do not contradict each other. Regeneration is a
recorded follow-up.

### 2. `docs/reference/benchmarks/atlas-mapping.md`

Replace the body of `## Coverage scope (honest)` (current lines 100-107: intro sentence, the
two-row "Partial" table, and the "See issue #264 ..." sentence). Heading text unchanged so the
anchor stays. New content, in this order:

1. One intro sentence: these two tactics describe adversary activities (getting access to a model,
   preparing an attack) rather than outcomes on a target, so their coverage needs a note; the
   numbers below come from `uv run python benchmarks/atlas_coverage.py --json` and the script is
   the source of truth.
2. A table with columns `Tactic | Technique | Vectors | Basis`, one row per technique:

   | Tactic | Technique | Vectors (develop @ 7e1ef38) | Basis |
   |---|---|---:|---|
   | `AML.TA0000` AI Model Access (3/4) | `AML.T0040` AI Model Inference API Access | 468 | Premise of every scan (see below) |
   | | `AML.T0047` AI-Enabled Product or Service | 457 | Premise of every scan (see below) |
   | | `AML.T0044` Full AI Model Access | 2 | Model-theft vectors (`mt_systematic_extraction`, `mt_deterministic_weight_approximation`) |
   | | `AML.T0041` Physical Environment Access | 0 | Out of scope: ZIRAN tests software agents over their APIs and has no physical access to the deployment |
   | `AML.TA0001` AI Attack Staging (7/7) | `AML.T0042` Verify Attack | 384 | Tagged on prompt-injection, tool-manipulation and indirect-injection vectors |
   | | `AML.T0043` Craft Adversarial Data | 175 | Tagged on prompt-injection vectors (the payload is the crafted adversarial data) |
   | | `AML.T0018` Manipulate AI Model (and `.000` / `.001` / `.002`) | 19 / 17 / 17 / 13 | Shared with `AML.TA0006` Persistence |
   | | `AML.T0005` Create Proxy AI Model | 1 | Model extraction (`mt_systematic_extraction`) |

   The "Basis" wording may be tightened, but every number MUST be the value from the
   implementation-time run. If any number differs from this table, use the new number and say so
   in the PR body.
3. One paragraph stating plainly: `AML.T0040` and `AML.T0047` coverage comes from the premise that
   every ZIRAN scan reaches the target through its inference API, inside an AI-enabled product or
   service. It is not a separate model-access attack; read these two counts as context, not as a
   distinct capability.
4. One sentence: per-tactic vector totals printed by the script add up per-technique counts, so a
   vector tagged with several techniques counts once per technique (e.g. TA0000 shows 927 for a
   661-vector library); the table above therefore lists techniques.
5. One sentence: no dedicated staging or reconnaissance vectors are added for AI Attack Staging,
   because adversary-side staging has no observable outcome on a target and tagging vectors with
   it would pad counts.

The "See issue [#264](...) for the follow-up work ..." sentence MUST NOT remain. No other section
of the page changes.
